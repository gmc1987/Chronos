# Chronos 教务机构隔离与批量导入技术实施方案

## 1. 目标与现状

交付范围是管理后台的机构查询、数据写入、关联对象选择、导入导出和权限验证。门户、移动端、智能体和定时任务若共用相关业务服务，同步核对调用契约。保留现有模块目录和菜单，不新建一套平行的教务管理入口。

本轮已有改动可作为基线。权限管理、请假余额、维修人员、集体备课的员工查询已补传机构。教学日历已支持选择机构与学期、校验归属、批量粘贴预检及提交。行政班、报修单、维修物料已接入部分机构查询。前一轮已有走班周课表和公告范围选择改动。接手时检查当前工作树和接口，并补齐异机构拒绝、单机构默认、关联选择、旧调用兼容和浏览器验证。编译通过的页面仍需完成业务验收。

当前代码的入口包括后端 `Chronos/platform-iam`、`Chronos/education-class-scheduling`、`Chronos/facility-maintenance` 与前端 `Chronos-UI/src/modules`。机构目录先查 `OrganizationController`、`DirectoryDataScopeGuard`，教育授权先查 `EducationDataScopeService`，通用前端选择器先查 `OrganizationSelect.vue`。页面清单从路由注册与实际菜单数据交叉核对，同一组件复用在不同入口时分别核对权限、请求和操作。

## 2. 机构和权限契约

### 2.1 页面行为

| 账号范围 | 初次进入 | 机构切换 |
| --- | --- | --- |
| 无可访问机构 | 显示“当前账号没有可访问的机构”，业务表格为空，禁用写操作 | 无 |
| 仅一个可访问机构 | 自动使用该机构。表头可展示只读机构名称 | 无 |
| 集团或多机构管理员 | 优先恢复该模块上次选中且仍有权限的机构。没有可恢复值时提示选择 | 仅能切换有业务权限的机构 |
| 平台全局管理员 | 同样以具体机构作为业务上下文 | 可选择全部有效机构。跨机构聚合只在有明确业务用途且单独授权的报表或审计入口提供 |

校区是机构树中的节点。学校归属的数据按 `organizationId` 精确匹配。校区归属的数据优先通过明确的 `campusId` 查询。学校视图确实需要看下属校区时，在后台解析当前学校下有效且有权限的校区，界面标明“包含下属校区”，写入仍明确到目标校区。集团节点用于导航或专门汇总，不默认作为学校档案的所有者。机构选项以当前会话权限和页面支持的机构类型为准。

复用 `OrganizationSelect.vue`，增加机构上下文组合函数负责选项、默认值、状态和过期请求处理。模块保留自己的联动逻辑。切换机构时，清空表格、页码、学期、班级、课程及其他依赖项，关闭旧机构的编辑、派单、预览弹窗。校验请求和结果归属，丢弃旧请求响应。机构记忆以用户和模块为键，重新登录后重新校验。新建表单显示已选机构，从该机构加载候选，正常编辑锁定原归属。

### 2.2 服务端约束

- 区分机构访问、动作权限、记录可见范围三层。统一从登录主体计算授权机构。针对教学班、任课、成绩复核、考试审核等业务，再与现有班级、教师、学生、流程角色范围取交集。具有组织读权限不自动获得导入、审核或发布权限。
- 管理端查询统一接受 `organizationId`，校区级业务可附 `campusId`。多机构会话缺失机构参数时返回“请选择机构”。单机构会话允许服务端推断。明确区分空授权集合与全局授权，空授权集合返回空或拒绝。过渡期间保留已识别的非管理调用契约，逐个迁移消费者。停止无条件放开兼容查询前，回归门户、原生应用、小程序、Agent 和后台任务。
- 组织条件进入 Repository、Specification 或 SQL，先过滤再排序、分页、计数、汇总。关联查询通过带归属的父表约束。每个导出、统计、候选搜索沿用同一范围，避免列表与总数、附件、导出内容不一致。
- 按记录 ID 读写时先查真实所有者，再校验当前动作权限。新建校验请求机构和父记录归属一致。更新同时校验原归属和所有新增关联。删除、附件上传下载、导出、审核、发布、回滚、派单、入库都纳入。普通更新不迁移记录归属。遇到跨校转学、跨校考试、联合办会等既有流程，保留显式授权关系与业务审批。
- 对外保持既有响应结构。参数错误、无权访问、重复键、并发冲突分别映射 400、403、409 等对应业务结果。明细接口按既有安全约定处理不可见记录，避免借由报错泄露记录存在性。前端统一显示业务消息，局部表单和批次定位到字段或行。
- 异步作业、Agent 工具和流程回调保存明确的目标机构及业务主键。执行或重试时校验当前操作者权限。审批人资格、自审限制等由原业务服务判断。缓存键、幂等键和审计事件包含机构范围。

## 3. 数据归属与历史迁移

| 类型 | 归属策略 | 查询和写入 |
| --- | --- | --- |
| 学期、教学日历 | 学期拥有学校机构，校历继承学期 | 日历列表传机构和学期；所有写入、同步、批量导入验证学期所有者。不同学校同一天可以配置不同校历 |
| 作息方案和节次 | 方案关联学期与校区，节次继承方案 | 校验学期学校和作息校区的关系，节次详情和写入沿方案反查 |
| 年级、专业、课程、学科 | 保留已有共享目录及历史引用。增加各学校目录映射作为第一阶段，支持启停和校内显示名。只有确实要自建的条目才增加学校私有项 | 学校业务通过“本校启用目录＋本校私有条目”读取。平台共享目录维护另设权限。原有条目 ID 继续可用于历史回显。写入班级、教学任务前校验本校是否启用 |
| 行政班、教学班、学生、任教关系 | 行政班及教学任务按已有校区字段；学生沿当前有效学籍及班级，历史记录沿当时快照；教师档案沿任职或有效组织关系，任教沿教学任务 | 跨校任教允许明确授权，教师选项按所在教学任务机构和有效任职范围加载。转班、转专业、跨校转学走已有业务入口 |
| 家长档案、账号及绑定 | 家长身份和账号保持全局唯一逻辑。可见范围通过监护关系及其关联学生所属学校确定 | 学校可见其学生关联和必要家长信息。家长跨校关联分别授权。无学生关联的新建档案，应与首条监护关系在同一事务落库；如必须先建档，使用带明确所有者的待关联记录 |
| 其他业务单据及明细 | 可直接确定的单据保存组织归属；明细继承考试、成绩册、会议、作业、工单等父记录 | 避免为每张明细机械新增机构字段。冗余归属确有性能需求时，增加外键或一致性校验，并覆盖更新路径 |

实施迁移时先统计现有字段、关联、空值、跨校关系、重复键，输出按表和机构汇总的只读报告。回填优先使用已有机构字段、唯一确定的父记录或有效业务关系。多归属家长保留共享身份与多条关系。没有可靠来源的记录进入待核对清单，保留原始记录；禁止按创建人、admin 所在机构或第一所学校猜测。校级查询不能把未归属记录视为共享。

Flyway 采用扩展、回填、切流、收紧四步。先部署向后兼容的列或映射、索引和可审计回填，演练后再收紧约束。自然键按业务决定是否加 `organization_id`，例如学期编码、校内课程编码和维修物料编码。全局账号及档案主键保持原有唯一性。确认数据库约束后再使用 `ON CONFLICT`。为所有者、状态、排序键以及常用关联键建立适配查询的索引，通过两校数据和实际分页 SQL 检查。保留数据库备份和回填核对报告，回滚以停用新增入口或恢复旧应用版本为主，避免在回滚时删除新写入的业务记录。

## 5. 批量导入统一实现

### 5.1 用户操作

1. 先选机构和适用的学期、校区或业务父记录。展示当前模板版本和允许的操作。
2. 下载带样例、字段说明和选填规则的 XLSX 模板。小批次场景可保留粘贴表格，例如教学日历。
3. 上传到项目现有受管文件中心，选择预检。返回有效数、错误数、重复数、拟新增数、拟更新数和按行的差异预览。错误较多时提供下载，敏感字段按权限脱敏。
4. 用户确认后提交。返回批次编号、结果和审计信息。切换机构后失效当前预览。
5. 结果保留模板版本、目标机构、操作人、时间、文件摘要及行结果。错误文件和原文件按已有存储和保留策略处理。

### 5.2 参考接口与实现边界

优先复用招生、住宿、员工、成绩和题库现有能力，统一行为和响应结构。可在模块内实现以下参考协议，保留已有调用的兼容入口。

```text
GET  /admin/<resource>/import/template
POST /admin/<resource>/import/preview
POST /admin/<resource>/import/commit
GET  /admin/<resource>/import/batches/{batchId}
```

预检请求至少包含 `organizationId`、`managedFileId`、`templateVersion`，按业务增加 `termId`、`campusId`、`parentId` 和 `mode`。提交使用 `previewId` 和幂等键，服务端校验预检所属操作者、目标机构、文件摘要、版本与过期时间，并重新校验权限和数据冲突。上传文件、预检结果和批次详情都按机构和权限读取。模板每行的机构字段如存在，只用于一致性校验，不能覆盖批次机构。

每个导入器负责字段解析、标准化、机构内关联查找、行业规则和幂等业务键。公共层负责文件限制、错误模型、批次状态、幂等与审计。工作簿限制大小、行列数与解压体积；拒绝公式作为写入数据；编号按字符串保留前导零；日期与枚举做明确转换。预检仅读取业务数据。提交调用既有业务校验，小批次默认全成或全败，跨实体初始化按依赖顺序写入。同一业务键发生并发写入时由数据库唯一约束兜底，返回冲突并提供重新预检入口。大批次确需分片时，明确披露部分成功语义，持久化进度与行级幂等，重试只执行未完成部分。

导入默认只新增。若需要更新，提供独立模式、动作授权和差异预览。禁止靠导入删除记录、覆盖已发布课表、直接完成成绩复核、修改家长账号绑定或绕过库存台账。历史迁移若确有例外，应单独设计权限、审计和校验。

### 5.3 住宿人工分配批量导入

在住宿分配的「人工分配」页签新增「批量导入」入口。操作员先选择机构和学期，再下载 XLSX 模板、上传预检并确认。宿舍楼、房间、床位由住宿资源入口提前维护。

模板必填列为**学号、楼栋编码、房间号、床位号**，备注选填。编号列按文本处理，保留前导零。后端按机构内学号匹配学生，按「楼栋编码 → 房间号 → 床位号」逐级定位床位。机构和学期以批次选择为准，匹配不到或匹配出多条时返回行级错误。

预检验证操作权限、学期归属、学生住宿资格、学生和床位归属、床位启用与占用状态，以及现有人工分配的限制（例如楼栋性别规则）。同一批次重复学生、重复床位，或学生在该学期已有有效分配时，返回对应行号。预览显示每行匹配的学生和目标床位，便于确认。

确认时复用现有人工分配服务及其校验，在同一事务中重验学生和床位状态并整批写入。核对数据库约束和并发控制，确保单条人工分配与批量提交竞争同一床位时至多一方成功。遇到冲突整批回滚，提示重新预检。重复提交同一批次返回原结果，成功后刷新分配列表与可用床位数。已有住宿需要调整时，使用换宿或撤销流程。

浏览器验收覆盖成功分配多名学生、跨机构学生或床位、重复学号或床位、已有有效分配、预检后床位被占用和重复提交。失败场景核对整批无新增记录，成功场景核对已分配列表和床位占用状态。

## 6. 实施顺序与交付条件

| --- | --- | --- |
| A | 建立全量菜单台账，统一查询契约、前端机构上下文和缺参提示。修复既有员工查询、校历、行政班、报修和公告的剩余边界 | 两个机构各有数据。用单校、多校和 admin 分别验证，切换时列表、详情、写入和下拉均无串校 |
| B | 教务基础数据、共享目录映射、校历与作息、班级、学生、任教关系，完成迁移演练与高频导入 | 新老数据都能正确读取。回填报告可解释所有未归属记录。历史课表、学籍和账号引用正常 |
| C | 走班排课、考试、成绩、教学、作业、学生及班级中心剩余菜单 | 完成两校课表、考试与成绩闭环。教师、考务审核员和学生等角色以真实业务身份执行；候选、统计和导出范围一致 |

Copilot 先交阶段 A 的台账与契约，再按依赖分批提交。每批提供菜单、涉及接口、迁移影响、测试结果、尚未覆盖项和复现路径。尊重当前工作树已有改动。机构筛选应与服务端权限一起交付，已有审批和业务状态机一并回归。

## 7. 浏览器与接口验收

使用隔离验收库准备 A、B 两所学校和 A 的一个下属校区。两校设相同本地学期编码及部分相同目录编码，准备家长跨校绑定、跨校任教、跨机构邀请和维修人员不同责任范围。账号覆盖 admin、集团管理员、A 校管理员、仅 A 校教师、B 校业务账号、无机构账号，以及具有审批权限但无发起权限的审核人。

- **浏览器**。逐页确认默认机构、切换、选择联动、分页、详情、创建、修改及刷新恢复。验证快速切换时旧响应不会回写。确认用户能看到权限、参数、冲突和导入错误提示。沿用既有要求，保留验收台账和演示数据，无需生成截图。
- **机构权限**。使用真实账号发起异机构列表、分页、详情、修改、删除、导入、导出及关联查询。验证拒绝且数据未变化。验证存在可访问子校区、没有子校区权限、拥有显式跨校业务授权三种情况。
- **批量导入**。同一文件在机构 A 预检，切到 B 后提交应失败。覆盖文件含重复键、错误父记录、同编码异校、失效模板、预检后权限撤销、预检后数据被修改、重复提交、并发提交及批次历史隔离。确认失败时没有残留记录和附件授权。
- **真实业务闭环**。完成两校校历差异、走班求解至审核发布、考试排考和成绩复核、家长会邀请、跨机构会议邀请、维修派单及物料台账。核对数据库中的所有者和引用、业务状态及审计事件。
- **发布验收**。执行前后端构建、与本次改动相关的单元和集成测试、两校数据迁移演练。浏览器台账记录账号角色、机构、菜单、操作、预期与实际结果；仅完成静态检查或接口测试的项目分别标注。

完成定义是用户在自己的授权机构中走完业务，且另一个机构的同名、同编码记录无法经列表、详情、关联或批量入口被读写。已有跨机构流程必须在其显式业务授权范围内通过。
