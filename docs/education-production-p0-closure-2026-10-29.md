# Chronos 教育生产化 P0 闭环台账（2026-10-29）

## 1. 目标与口径

本轮以“单校部署的高职院校生产版”为第一交付基线，兼容大专、本科的共同业务，不把中小学特有政策强行混入同一状态机。关闭一项 P0 必须同时具备：人工操作入口、服务端状态机、数据范围、职责分离、审计与历史版本、失败边界、数据库迁移、接口验证和浏览器业务验证。

已有演示数据或页面存在不等于本项关闭；构建成功也不等于业务验收成功。Agent 只能调用已经闭环的业务工具并生成候选，不得绕过人工确认、审批、发布和归档。

## 3. 实施顺序

1. P0-01 与 P0-02：建立后续考试、成绩、排课共同依赖的正式教务事实源。
2. P0-04 与 P0-05：补齐高职学生在校生命周期和实践教学。
3. P0-06 与 P0-07：只补现有考试、成绩领域缺口，不重复建模。
4. P0-08 与 P0-09：完成家校隐私治理及后勤资产运维。
5. P0-10：使用隔离发布副本完成跨角色、数据库、文件、故障和浏览器验收。

## 4. 关闭证据模板

每一项关闭时必须记录：

- 迁移版本和当前 Git 提交；
- 新增或变更的接口契约；
- 发起人、维护人、审核人、发布人及无权账号；
- 正常、驳回、撤销、并发冲突、重复提交和越权结果；
- 发布前后数据库快照与审计记录；
- 前端人工入口和 Agent 工具入口；
- 自动测试、Postman 实际接口结果及浏览器业务编号；
- 目标环境仍需复跑的配置、容量和外部集成项。
