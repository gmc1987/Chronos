# Chronos 下一阶段教务运营优化计划

2026-11-09 确认为 Chronos 的下一阶段目标。实施从 EDU-01 开始，EDU-01 与 EDU-02 一起完成 P0 验收后进入 P1。

下一阶段优先交付教学变更台和教师课时台账，再补巡堂、迎新报到和毕业离校。以高职演示院校为主验收，使用另一机构验证数据隔离。所有正式操作保留人工入口，运营智能体复用同一业务服务、权限和确认策略。

## P0 优化方案

**复用日期课表作为变更结果的统一入口。** 周课表继续作为周期模板，临时停课、补课、代课与考试占课以具体日期和节次生效。先盘点现有记录与审批来源，优先扩展现有模型。学校批量停课时，先按范围预览并冻结涉及节次，确认或审批后执行。原课次保留可追踪记录，待补课可安排在前后任意符合条件的日期。涉及教师、教学班、学生或教室冲突时，界面显示具体冲突并阻止冲突节次生效。

**把审批状态和课表生效状态分别展示。** 审批通过后若回写失败，变更台应显示受影响节次、失败原因和重试入口。重复提交或回写按同一业务记录去重。撤销前校验后续安排，涉及已发生的授课或已确认课时，应走更正并保留原记录。

**把应授课时与实际授课分开。** 发布课表生成应授，停课标记取消或待补，补课关联原节次，代课的实际课时归授课教师。缺少实际授课凭证时标记待确认。台账支持下钻到日期课次、变更单和确认记录。第一版以节次和实际分钟为基础，学校确认后再启用折算口径。

**人工与 Agent 共用规则。** P0 人工入口先完成。Agent 第一批支持查询影响、解释冲突和生成变更候选。正式提交复用现有确认与审批策略，独立审核仍按业务权限执行。浏览器验收分别覆盖人工操作、单轮对话和在原对话补参数的多轮操作。

## 验收与关闭条件

| 用例 | 通过条件 |
|---|---|
| P0-01 专业临时停课 | 教务从浏览器预览影响，生效后只有选定范围课次暂停，待补课清单与师生日期课表一致。 |
| P0-02 补课与代课 | 先验证冲突被拦截，再完成无冲突安排和适用审批。师生课表显示新时间和代课教师，教师课时明细可追溯且无重复计数。 |
| P0-03 回写与撤销 | 构造可恢复失败并从变更台重试。浏览器可见原因和恢复结果，重复重试无重复记录，撤销与更正有审计。 |
| P0-04 机构隔离 | 普通教务、教师和审核人分别验证授权操作与越权拒绝，涵盖页面、导出和 Agent。 |
| P1-01 至 P1-03 | 巡堂完成整改复查，新生完成补件到报到，毕业完成资格实算到离校核查。每条链分别记录页面结果、业务编号及数据库核对结果。 |

沿用现有验收台账，记录日期、环境、角色、用例、业务编号、预期与实际结果。保留演示数据，验收不生成截图。P0 用例全部通过后再进入 P1。现有 Agent 同一对话排课的独立审核、应用与发布，以及 Agent 直接审批正向和智能授权实配的待验项，继续在原台账跟踪。毕业资格实算纳入 EDU-05 的前置验收。参考[现有运营智能体验收台账](acceptance/2026-11-07-operation-agent-llm-conversation.md)。
