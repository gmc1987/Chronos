# Chronos 流程中心说明与演进计划

## 1. 文档目的

本文记录 Chronos 流程中心当前的产品边界、配置模型、设计与运行流程、节点语义、已经完成的能力和后续待办。它既是当前状态说明，也是后续开发和验收依据。

功能验证可使用 [流程中心演示数据说明](workflow-center-demo-guide.md) 和配套的 `docs/sql/workflow-center-demo-data.sql`。

## 2. 产品定位

流程中心用于让管理员通过可视化画布定义医院办公和业务审批流程，并由统一流程引擎负责版本、任务、路由、时限、自动执行和审计。

典型场景包括请假、采购、合同、用印、信息化申请、医疗业务审批和跨部门协同。

流程中心由以下部分组成：

1. 流程定义与版本管理。
2. 可视化流程画布。
3. 表单定义、实例和字段权限。
4. 审批人、办理人和抄送人规则。
5. 条件分支、并行网关和子流程。
6. 流程发起、任务处理和业务操作。
7. 自动节点和外部系统集成。
8. 办理时限、催办和通知。
9. 流程监控、异常恢复和统计分析。
10. 权限、安全和审计治理。

## 3. 总体架构

Chronos 采用“自定义设计器 + Flowable 执行内核 + Chronos 业务扩展”的架构。

```text
Chronos Vue 流程设计器
        ↓
Chronos 流程定义、节点、连线和表单配置
        ↓ 发布与规则检查
BPMN 2.0 模型转换
        ↓
Flowable 8 Process Engine
        ↓
人工任务 / 条件路由 / 定时器 / 自动节点
        ↓
IAM / Form / Message / Agent / Integration / Scheduling
```

当前发布时已经生成并部署 BPMN 模型。已有流程实例暂时仍由旧的轻量状态机推进，待任务中心和执行器适配完成后统一切换到 Flowable，避免双引擎同时推进同一个实例。

## 4. 流程定义

### 4.1 基础字段

| 字段 | 作用 | 配置方式 | 当前状态 |
| --- | --- | --- | --- |
| 流程编码 | 稳定标识一个流程，不随名称变化 | 新建时填写，创建后锁定 | 已完成 |
| 流程名称 | 面向用户展示的业务名称 | 文本 | 已完成 |
| 流程分类 | 门户分组、搜索和管理 | 字典下拉 | 已完成 |
| 版本 | 区分同一流程的不同发布版本 | 新建时确定，发布后创建新版本 | 已完成 |
| 描述 | 说明适用范围、办理要求和注意事项 | 多行文本 | 已完成 |
| 主表单 | 承载流程核心业务数据 | 表单定义选择 | 已建立绑定，设计器待完成 |
| 入口节点 | 流程启动位置 | 当前选择开始节点，后续自动识别 | 已完成，可继续简化 |
| 状态 | 草稿、已发布、已停用 | 系统自动维护 | 后端完成，前端待移除手动选择 |
| 流程管理员 | 维护、发布和处理异常的责任人 | 应改为 IAM 用户/角色选择 | 当前仅存储账号 |
| 发起范围 | 限制可以发起流程的人 | 应改为组织/角色/人员范围选择 | 当前存储 JSON，尚未强制执行 |
| 标签 | 搜索和运营标记 | 应改为多标签组件 | 当前普通文本 |
| AI 辅助 | 启用私有化 AI 增强检查 | 高级设置开关 | 已有开关，Provider 待完善 |
| 配置 JSON | 流程级扩展配置 | 仅开发/高级模式 | 当前存储，业务运行未使用 |

### 4.2 生命周期

```text
新建 → 草稿 DRAFT → 规则检查 → 发布 PUBLISHED → 停用 DISABLED
                              └→ 基于已发布版本创建新草稿版本
```

- 草稿可以修改，但不能正式发起。
- 已发布版本不可直接修改或删除。
- 调整已发布流程时，应创建新版本。
- 新实例使用指定的已发布版本；运行中的实例保持原版本。
- 已停用版本不能发起新实例，但历史实例和记录必须保留。

当前已经支持发布、停用和复制新版本，新版本会复制节点、连线、表单绑定和字段权限。

## 5. 流程设计流程

### 5.1 管理员设计流程

1. 新建流程，填写编码、名称和分类。
2. 系统自动创建唯一开始节点和一个结束节点。
3. 选择主表单。
4. 按“人工、自动、控制”分类添加节点。
5. 配置节点属性、处理人、附加表单和字段权限。
6. 连接节点；条件分支在线上配置条件和默认分支。
7. 保存草稿。
8. 执行确定性规则检查，可选 AI 增强检查。
9. 检查通过后转换为 BPMN 并部署到 Flowable。
10. 发布版本，允许符合发起范围的用户使用。

### 5.2 用户运行流程

目标运行流程如下：

1. 用户从门户选择流程。
2. 系统检查流程状态和用户发起权限。
3. 根据主表单渲染申请页面。
4. 保存草稿或正式提交。
5. Flowable 创建流程实例并进入第一个任务或自动节点。
6. 人工节点生成待办；自动节点异步执行。
7. 每个节点按字段权限渲染主表单和附加表单。
8. 条件、并行、定时和子流程节点由引擎推进。
9. 到达结束节点后归档业务数据和完整审计轨迹。

当前运行时只完成了轻量级发起、简单条件、人工待办和完成任务，尚未完成表单渲染、复杂任务操作和 Flowable 实例统一切换。

## 6. 画布能力

### 6.1 已完成

- 新建流程自动生成开始和结束节点。
- 节点双击编辑。
- 节点拖拽和位置持久化。
- 无碰撞网格落点。
- 无限平移画布，缩放范围 10% 至 250%。
- 自适应画布高度和一键复位。
- 节点连线。
- 双击连线配置条件和默认分支。
- 删除普通节点并同步删除关联连线。
- 开始和结束节点禁止删除。
- 开始节点唯一、禁止入线。
- 结束节点至少一个、禁止出线。
- 发布前检查断线、死路、环路和不可达节点。

### 6.2 推荐增强

- 缩略图。
- 撤销和重做。
- 框选、多选、批量移动和复制粘贴。
- 自动布局和对齐辅助线。
- 节点搜索和快速定位。
- 子流程折叠。
- 未保存状态提示和自动保存。
- 流程版本差异对比。

## 7. 节点模型

### 7.1 节点分类

| 分类 | 节点 | 用途 |
| --- | --- | --- |
| 人工节点 | 审批 APPROVAL | 人员作出同意、拒绝等审批决定 |
| 人工节点 | 办理 TASK | 人员完成填写、补充、核验等工作 |
| 人工节点 | 抄送 CC | 通知指定人员并保留已读记录 |
| 自动节点 | 内部服务 SERVICE_TASK | 调用白名单 Spring 业务服务 |
| 自动节点 | HTTP API HTTP_TASK | 调用集成中心管理的外部接口 |
| 自动节点 | AI Agent AGENT_TASK | 调用 Agent Runtime 中发布的 Agent |
| 自动节点 | 消息 MESSAGE_TASK | 通过消息中心发送通知 |
| 控制节点 | 开始 START | 唯一流程入口 |
| 控制节点 | 条件 CONDITION | 按条件选择一条出口 |
| 控制节点 | 结束 END | 结束流程，可存在多个不同结果出口 |

后续需要增加并行网关、定时等待和子流程。

### 7.2 通用配置

- Key：节点在流程版本内的稳定标识，连线和运行记录通过它引用节点。
- 名称：画布、待办和历史记录中的展示名称。
- 类型：决定节点执行语义和编辑器显示内容。
- 附加表单：仅在该节点额外展示和填写的表单。
- 字段权限：控制主表单及附加表单字段的可编辑、只读、隐藏和节点必填。
- 高级配置：底层 JSON 扩展容器，普通业务用户不应直接编辑。

### 7.3 人工节点配置

- 处理人规则：指定用户、角色、发起人直属领导或表单字段。
- 处理人参数：账号、角色编码或字段 Key。
- 审批方式：单人、任意一人、全部通过。
- 办理时限：任务到期时间，后续用于催办和升级。
- 退回策略：上一节点、发起人或可选择节点。
- 字段权限和附加表单。

当前配置界面已经完成，人员规则解析、多人任务和退回运行逻辑尚未全部完成。

### 7.4 自动节点配置

- 执行器：内部服务、HTTP、Agent 或消息适配器。
- 执行超时：单次调用的最大时长。
- 重试次数和间隔：失败后的自动恢复策略。
- 输入 Schema：执行器接收的数据结构。
- 输出 Schema：执行结果结构。
- 输入输出映射：后续改成可视化映射，不要求用户手写 Schema。

当前已建立执行器能力目录，但四类执行器仍处于待接入状态。自动节点未配置可用执行器时应阻止发布。

### 7.5 条件节点与连线

条件配置在线上而不是节点本身，因为一个条件节点可以有多条出口。每条条件线包含：

- 条件表达式。
- 是否默认分支。
- 分支优先级，待实现。

当前支持简单比较表达式和默认分支，后续应使用可视化条件构建器替代手写字符串。

## 8. 表单与字段权限

### 8.1 主表单

主表单保存整个流程共享的核心业务数据。所有节点访问同一份主表单实例，但权限可以不同。

### 8.2 附加表单

附加表单只在指定节点出现，例如财务复核表、风险评估表和验收记录。需要明确数据归属、重复填写、退回保留和后续节点可见性。

### 8.3 字段权限

当前节点权限包括：

- EDIT：可编辑。
- READ：只读。
- HIDDEN：隐藏。
- 节点必填：仅在当前节点提交时校验。

当前已完成定义、实例、草稿/提交、动态渲染和后端字段级写入校验。附件字段目前只有渲染入口，实际文件上传将在 `platform-file` 接入阶段完成。

## 9. 发布检查

当前确定性检查包括：

- 节点类型是否合法。
- 人工节点是否配置处理人。
- 自动节点是否配置执行器。
- 是否存在且只存在一个开始节点。
- 是否至少存在一个结束节点。
- 入口节点是否有效。
- 连线是否引用存在的节点。
- 开始节点是否存在入线。
- 结束节点是否存在出线。
- 条件表达式是否合法。
- 是否存在多个默认出口。
- 是否存在死路、环路和不可达节点。
- 是否存在可到达的结束路径。

AI 检查是增强能力，不能替代确定性规则检查。

## 10. 权限与安全原则

- 流程管理需要 `workflow:manage`。
- 流程使用需要 `workflow:use`。
- 流程管理员和发起范围必须接入 IAM，而不是自由文本。
- 自动执行器必须使用白名单，不能任意调用 Spring Bean 或 URL。
- 敏感配置、认证信息和字段值必须脱敏。
- 所有发布、停用、任务处理、跳转和异常恢复操作必须写入审计日志。
