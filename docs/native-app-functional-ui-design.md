# Chronos 原生 App 功能界面设计说明

> 文档状态：设计基线  
> 适用范围：Chronos iOS、Android 原生客户端  
> 版本日期：2026-10-16

## 1. 设计目标

Chronos 原生 App 面向学生、教师、普通教职工、校领导和系统管理员提供统一移动入口。App 不复制 Web 门户的全部功能，而是聚焦移动场景中的高频查看、快速处理和及时触达。

核心目标：

1. 登录后根据服务端返回的真实身份、角色和权限动态生成界面。
2. 将“工作台”作为所有角色的首个 Tab，集中展示当前用户最重要的信息。
3. 保持 iOS、Android 与 Web 门户在品牌色、业务名称和权限规则上的一致性。
4. 所有卡片必须连接真实业务或明确展示建设状态，不请求虚构接口。
5. 服务端继续负责数据范围和业务权限校验，客户端只负责展示和入口过滤。

## 2. 设计原则

### 2.1 身份不可手动切换

- 学生登录后固定进入学生视角，不提供身份切换按钮。
- 教师登录后按照其岗位和管理权限自动确定教师视角或管理视角。
- 同时具有教师档案和校领导、管理权限的用户，优先进入管理工作台。
- 管理视角下仍可通过“应用”进入其有权限使用的教学功能，但工作台不混入教师专属组件。
- 客户端退出登录后才允许更换账号。

### 2.2 身份判定依据

身份判定使用 `/portal/bootstrap` 返回的数据综合计算：

- `contributions.DATA.data.profileTypes`：教育身份，如 `STUDENT`、`TEACHER`、`PARENT`。
- `user.roles`：平台角色和学校管理角色。
- `user.permissions`：功能及数据访问权限。
- `applications`：服务端已经按权限过滤的可用应用。

禁止仅根据角色名称、角色数组顺序或客户端默认值推断身份。

### 2.3 工作台聚焦

- 学生工作台聚焦学习和个人课程安排。
- 教师工作台聚焦授课安排、待办和教学协同。
- 校领导及管理员工作台聚焦决策、督办和全局数据。
- 普通教职工工作台聚焦待办、会议和协同办公。
- 不将同一业务同时放在多个一级 Tab 中。

## 3. 视觉规范

### 3.1 品牌与色彩

- 主色：门户青绿色 `#087B68`。
- 深色强调：`#063D39`。
- 页面背景：浅灰 `#F4F7F8`。
- 卡片背景：白色 `#FFFFFF`。
- 主文字：深灰黑，建议 `#17202A`。
- 次文字：灰色，建议 `#71808A`。
- 危险或异常：红色。
- 待处理或提醒：橙色。
- 成功和正常状态：品牌绿色。

业务状态颜色必须同时配合文字或图标表达，不能只依赖颜色区分。

### 3.2 页面结构

统一页面由以下区域组成：

1. 顶部安全区域和页面标题。
2. 用户或学期摘要区。
3. 可纵向滚动的工作台内容。
4. 固定底部 Tab Bar。

卡片使用圆角、轻阴影和清晰分组。首页不使用大面积渐变，不在同一屏堆叠过多颜色。

### 3.3 跨平台一致性

- iOS 使用 SwiftUI 原生导航和交互。
- Android 使用原生 Material 组件。
- 两端信息层级、业务名称、图标语义和空状态保持一致。
- 返回、刷新、下拉、系统字体缩放等行为遵循各平台习惯。

## 4. 登录与会话

### 4.1 登录页

登录页延续当前门户风格：

- Chronos 品牌标识。
- 账号、密码输入。
- 密码显隐。
- 登录加载状态和防重复提交。
- 网络、账号、权限等错误的明确提示。
- 真机环境使用配置的局域网或 HTTPS 服务地址，不使用手机自身的 `localhost`。

### 4.2 登录后初始化

登录成功后按顺序完成：

1. 保存访问令牌和刷新令牌。
2. 请求 `/portal/bootstrap`。
3. 计算当前工作台类型。
4. 生成底部 Tab。
5. 加载工作台首屏数据。

初始化失败时不得显示错误角色页面。应保留登录状态并提供重新加载；身份数据无法获得且令牌失效时才退出登录。

## 5. 底部导航设计

### 5.1 导航矩阵

| 用户类型 | 底部 Tab | 默认首页 |
|---|---|---|
| 学生 | 工作台、成绩、考试、通知、我的 | 学生工作台 |
| 教师 | 工作台、应用、公告、我的 | 教师工作台 |
| 普通教职工 | 工作台、应用、公告、我的 | 职工工作台 |
| 校领导/管理员 | 工作台、应用、公告、我的 | 管理工作台 |

### 5.2 Tab 规则

- “工作台”始终排在第一位，建议图标 `rectangle.grid.2x2`。
- 学生课表整合进工作台，不再单独占用一级 Tab。
- “应用”只显示服务端返回且当前用户有权限访问的应用。
- “公告”展示当前用户可见的学校公告和通知。
- “我的”承载个人资料、设置、会话和退出登录。
- Tab 页面切换后保留各自滚动位置和筛选状态。

## 6. 学生工作台

### 6.1 页面目标

学生打开 App 后应立即看见本周学习安排，并能快速进入课件、错题和题库。

### 6.2 顶部学生信息

展示：

- 学生姓名。
- 所属班级。
- 当前学期。
- 当前日期和星期。

不展示身份切换入口。若账号未绑定有效学生档案，显示“学生档案未绑定”，并提供联系学校管理员的说明。

### 6.3 二维周课表

#### 6.3.1 基本结构

- 横轴：周一至周日。
- 纵轴：学校当前作息方案中的节次。
- 固定首列：节次名称及实际起止时间。
- 课程单元格：课程名称、教师、教室和课程状态。
- 默认显示当前周，并突出当天。

小屏设备采用横向滚动，节次列保持固定或具有明显视觉锚点，不能将七天课程压缩到不可阅读的宽度。

#### 6.3.2 周切换

课表标题区提供：

- 上一周。
- 回到本周。
- 下一周。
- 当前周日期范围。

切换周次后重新请求对应日期范围数据，并保留课表展开状态。

#### 6.3.3 课程状态

至少支持：

- 正常课程。
- 调课。
- 代课。
- 停课。
- 临时课程或其他服务端返回的有效状态。

状态必须由服务端课表结果决定，客户端不重新计算排课、调课或代课规则。

#### 6.3.4 展开与收起

课表卡片右上角提供“收起/展开”按钮。

展开状态：

- 显示完整二维周课表。
- 显示周切换控制和课程详情。

收起状态：

- 保留卡片标题和当前周日期范围。
- 显示今日课程数量、下一节课名称及时间；当日无课时显示“今日无课程”。
- 保留“展开课表”按钮。

用户选择应持久化到本地，下次进入工作台时恢复上次状态。首次登录默认展开。

#### 6.3.5 课程详情

点击课程单元格打开课程详情页或底部详情面板，展示：

- 课程名称。
- 教师。
- 教室。
- 上课日期和时间。
- 教学班或行政班。
- 调课、代课、停课说明。
- 可用时进入对应课程课件。

### 6.4 学习功能卡片

课表下方依次展示：

| 卡片 | 摘要内容 | 点击行为 |
|---|---|---|
| 课件 | 最新课件、未读或最近更新时间 | 进入本人有权访问的课程课件列表 |
| 错题沉淀 | 本人错题数、待掌握数或最近新增 | 进入“我的错题” |
| 题库 | 可练习题库或最近使用题库 | 进入学生可访问的练习入口 |

卡片必须使用真实接口。若某项学生端能力尚未开放：

- 服务端未返回应用或权限时隐藏卡片。
- 功能已规划但接口尚未上线时，可显示禁用的“建设中”状态。
- 禁止点击后请求不存在的地址。

### 6.5 学生其他 Tab

#### 成绩

- 学期筛选。
- 课程成绩列表。
- 总评、过程成绩及考试成绩摘要。
- 点击查看成绩详情。

#### 考试

- 即将开始、已结束分类。
- 考试名称、科目、时间、考场和座位信息。
- 对临近考试进行明确提醒。

#### 通知

- 班级通知、学校通知及与本人相关的教学通知。
- 未读标识。
- 详情页支持附件和已读回写。

#### 我的

- 学生基本资料。
- 班级和学籍摘要。
- 消息设置。
- 关于 App。
- 退出登录。

## 7. 教师工作台

### 7.1 页面目标

教师工作台同时服务授课安排、日常审批和教学业务，首屏优先展示当天需要处理的信息。

### 7.2 顶部教师信息

展示：

- 教师姓名。
- 所属部门或教研组。
- 当前学期。
- 当前日期。

不提供身份切换按钮。

### 7.3 教师二维周课表

课表结构和学生课表保持一致，但数据范围为当前教师本人授课安排。

教师课表同样支持：

- 上一周、本周、下一周。
- 调课、代课、停课状态。
- 点击查看教学班、班级、教室等信息。
- 展开和收起。
- 本地记忆展开状态。

收起时展示今日授课数量和下一节课，避免课表长期占用首屏空间。

### 7.4 教师工作台组件

推荐顺序：

1. 二维周课表。
2. 我的待办。
3. 近期会议。
4. 协同办公。
5. 教学中心。

#### 我的待办

展示：

- 待处理总数。
- 最近若干条待办。
- 流程名称、发起人、到达时间和紧急程度。

点击单条进入处理页；点击“查看全部”进入统一待办列表。

#### 近期会议

展示未来若干天与本人相关的会议：

- 会议主题。
- 日期和时间。
- 地点或线上会议方式。
- 本人参会状态。

点击进入会议详情或会议中心。

#### 协同办公

以业务快捷入口和数量摘要组合展示：

- 请假。
- 出差。
- 用车。
- 用印。
- 公文。
- 共享文件。
- 其他当前用户有权限访问的协同业务。

卡片显示本人待处理、进行中或未读数量，不展示无权限业务。

#### 教学中心

展示当前教师可用的教学能力：

- 课件。
- 教学材料。
- 题库。
- 错题沉淀。
- 备课等服务端已开放功能。

首页只展示摘要和入口，复杂编辑操作可进入专门页面；不适合移动端的管理操作可以只读展示并提示前往 Web 端。

## 8. 普通教职工工作台

普通教职工使用与教师相同的四个底部 Tab，但不显示教师课表和教学中心。

推荐组件：

1. 我的待办。
2. 近期会议。
3. 协同办公。
4. 学校公告摘要。

具体组件按服务端权限过滤。无任何业务数据时提供清晰空状态，不自动退化为学生工作台。

## 9. 校领导及管理员工作台

### 9.1 页面目标

管理工作台强调决策、执行监督和异常发现，不展示教师个人授课组件。

### 9.2 工作台组件

固定业务顺序：

1. 我的待办。
2. 近期会议。
3. 督办事项。
4. 数据概览。

#### 我的待办

- 展示需要当前领导或管理员审批、确认、处理的事项。
- 支持按紧急程度突出显示。
- 提供待办总数和快捷处理入口。

#### 近期会议

- 展示本人需要参加、主持或关注的会议。
- 突出今日会议和即将开始的会议。
- 点击进入会议详情。

#### 督办事项

展示：

- 待办、进行中、临期、逾期数量。
- 重点督办事项列表。
- 责任部门、负责人和截止日期。
- 状态和风险提示。

用户只能查看其数据权限范围内的督办事项。

#### 数据概览

根据权限展示学校或组织级关键指标。首期建议控制在四至六项：

- 在校学生数。
- 教职工数。
- 今日课程或教学运行情况。
- 待处理流程数。
- 会议或协同办公摘要。
- 异常或风险提醒。

数据概览只展示服务端返回的授权指标。不得因为用户拥有“管理员”名称就默认获取全校数据。

### 9.3 管理端其他 Tab

#### 应用

- 按业务域分组展示服务端授权应用。
- 支持常用应用、最近访问和搜索。
- 教师兼任管理人员可在此进入有权限的教学应用。

#### 公告

- 学校公告、管理通知和制度信息。
- 支持未读、置顶和分类筛选。

#### 我的

- 个人资料。
- 所属组织和岗位。
- 消息设置。
- 安全设置。
- 关于 App。
- 退出登录。

## 10. 应用中心设计

应用中心不维护客户端固定的完整应用清单，以 `/portal/bootstrap` 返回的 `applications` 为基础。

应用分组建议：

- 协同办公。
- 教学管理。
- 学生管理。
- 会议与日程。
- 文件与公文。
- 数据与管理。

每个应用项包含：

- 图标。
- 应用名称。
- 简短说明。
- 未读或待处理角标。
- 可用状态。

客户端根据服务端路由标识映射到原生页面。尚未有原生页面但允许移动访问的功能，可进入受控的 Web 页面；不支持移动访问的功能显示“请前往 Web 端处理”。

## 11. 公告与消息设计

公告页需要区分：

- 学校公告。
- 部门公告。
- 班级或教学通知。
- 系统消息。

通用能力：

- 未读角标。
- 置顶标识。
- 发布时间和发布组织。
- 附件查看。
- 下拉刷新和分页加载。
- 阅读后回写已读状态。

学生“通知”Tab 可突出班级和教学通知；教师及管理端“公告”Tab 以学校和部门公告为主。

## 12. 我的页面

“我的”保持所有角色结构一致，但根据身份展示不同资料：

- 头像、姓名和账号。
- 当前身份摘要，不提供身份切换。
- 学生显示班级和学号。
- 教师显示工号、部门或教研组。
- 管理人员显示岗位和组织。
- 消息通知设置。
- 隐私与安全说明。
- App 版本。
- 退出登录。

访问令牌不得展示给用户。正式版本应将令牌持久化从普通偏好存储迁移到系统安全存储。

## 13. 通用交互状态

每个组件都必须具备以下状态：

### 13.1 加载

- 首次加载使用骨架屏，避免整页空白。
- 局部刷新只更新对应卡片。
- 禁止同时弹出多个全屏加载提示。

### 13.2 空状态

空状态说明业务含义，例如：

- “本周暂无课程”。
- “当前没有待处理事项”。
- “未来七天暂无会议”。

不使用含义不明的“暂无数据”作为所有页面的统一文案。

### 13.3 错误

- 网络错误提供重试。
- 401 由会话层刷新令牌并最多重试一次。
- 403 显示“当前账号无权访问”，不伪装为空数据。
- 404 或接口不存在必须记录为功能配置错误，不显示成功状态。
- 单个卡片失败不应阻断整个工作台。

### 13.4 刷新

- 工作台支持下拉刷新。
- 周课表切换周次时独立加载。
- 返回工作台时根据数据更新时间决定是否静默刷新。

## 14. 权限与数据安全

1. 客户端根据权限隐藏无权入口，但这不是安全边界。
2. 服务端必须校验用户身份、组织范围、学生本人范围和教师任教范围。
3. 学生课表只能获取当前登录学生本人数据。
4. 教师课表只能获取当前教师本人或明确授权范围的数据。
5. 管理数据概览和督办事项严格按数据权限返回。
6. 日志不得输出访问令牌、刷新令牌、密码和完整敏感个人信息。
7. 附件和共享文件下载必须继续经过服务端权限校验。

## 15. 数据接口原则

移动端优先复用现有门户接口：

- 门户初始化：`GET /portal/bootstrap`。
- 个人课表：`GET /portal/education/schedule`。
- 周期课表：`GET /portal/education/schedule/calendar`。
- 成绩、考试、通知等使用现有门户真实接口。

实施前必须核对每个卡片对应的实际接口和响应模型。接口不存在时先补充服务端能力或将功能标记为建设中，不得在客户端自行拼接猜测路径。

建议后续为移动工作台补充统一摘要接口，减少首屏并发请求数量，例如一次返回待办数、近期会议、组件摘要和更新时间；详细列表仍由各业务接口按需加载。

## 16. 本地状态持久化

允许保存：

- 课表展开或收起状态。
- 最近选择的周次仅在当前会话保留，重新进入默认回到本周。
- 各 Tab 的滚动位置。
- 非敏感筛选条件。

不允许使用本地缓存替代服务端权限判断。用户退出登录时清除与账号绑定的工作台缓存和展示偏好。

## 17. 无障碍与适配

- 支持系统字体缩放。
- 主要点击区域不小于 44pt/48dp。
- 所有图标提供可读标签。
- 课表横向滚动时保留明确的日期和节次上下文。
- 支持深色模式可作为后续阶段；首期至少确保浅色模式完整一致。
- 适配刘海屏、灵动岛、Home Indicator 和 Android 系统导航区域。

## 18. 实施优先级

### 第一阶段

- 动态身份判定。
- 新底部 Tab。
- 学生工作台。
- 学生二维周课表及收起功能。
- 课件、错题沉淀、题库入口。
- 教师工作台基础组件。
- 管理工作台基础组件。

### 第二阶段

- 待办和会议的完整原生处理流程。
- 协同办公摘要和快捷操作。
- 督办事项详情。
- 数据概览图表。
- 应用中心搜索、收藏和最近访问。

### 第三阶段

- 离线缓存策略。
- 推送通知和深链跳转。
- 深色模式。
- 平板和横屏增强布局。

## 19. 验收标准

### 19.1 通用

- 登录后首个 Tab 为“工作台”。
- 界面类型与服务端身份、角色和权限一致。
- 任一角色均不显示身份切换入口。
- 切换 Tab 不丢失页面状态。
- 无权限入口不可见，直接访问仍由服务端拒绝。

### 19.2 学生

- 只显示本人课表。
- 课表按学校作息方案显示节次和真实时间。
- 支持完整二维展示、周切换、展开和收起。
- 收起状态重启 App 后仍可恢复。
- 课件、错题沉淀和题库只连接真实可用能力。

### 19.3 教师

- 显示本人授课课表且支持收起。
- 工作台包含我的待办、近期会议、协同办公和教学中心。
- 不显示无权限业务或其他教师的数据。
- 底部 Tab 为工作台、应用、公告、我的。

### 19.4 校领导及管理员

- 工作台只展示我的待办、近期会议、督办事项和数据概览。
- 不展示教师课表和学生学习组件。
- 数据概览严格符合组织和数据权限范围。
- 兼任教师的管理人员可从应用中心进入授权教学功能。

### 19.5 普通教职工

- 不被错误识别为学生。
- 工作台展示待办、会议和协同办公等授权组件。
- 不展示教师课表和教学中心。
