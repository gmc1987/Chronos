# 智慧校园第一阶段 MVP 实施基线

本文以《AI Native 智慧校园综合平台》第 56 节“第一阶段 MVP”明确列出的二十项能力为范围：用户、组织、权限、教师、学生、班级、课程、Form Engine、Workflow Engine、待办、请假、调课、基础排课、通知、文件、AI 助手、Knowledge Base、Scheduling Agent、AI 教务 Agent、审计。实施原则是先形成真实可运行的业务闭环，再对排课、流程、权限、知识库和 Agent 做生产级深化。

## 实施阶段

1. 校园基础数据：年级、学科、家长、监护关系、教师任教关系。
2. 教务业务：课程开设、教学班成员、多维课表、教学计划基础数据。
3. 流程业务：教师请假、学生请假、调课、教室申请及业务回写。
4. 门户协同：角色化首页、个人课表、待办、消息和通知。
5. 知识与 AI：知识库、AI 助手、Scheduling Agent、AI 教务 Agent。
6. MVP 验收：权限隔离、真实流程、冲突并发、附件和审计检查。

## 已验证的关键闭环

- 学生请假流程可以真实发起、生成班主任候选任务、认领审批并由 Flowable 正常结束。
- 调课审批完成后会在独立事务中幂等回写正式课表；失败时保存表单快照和错误原因，管理员可修复数据后人工重放。
- 请假审批完成后会形成独立业务台账，并通过消息 Outbox 可靠投递站内通知。
- 知识库文本导入、分段、中文检索、带来源问答和删除清理已通过运行态验证。
- Scheduling Agent 的约束草稿在人工确认前不会改变正式约束，确认后才写入业务表。
- 课表发布会生成不可变快照，回滚会追加新版本而非覆盖历史；V1 回滚到 V2 后 20 条课表完整恢复。
- 管理端教师、教学班、行政班、学生和教室多维课表已通过真实关联数据验证；普通教师门户只读取最新发布版本。
- 家长门户可在有权监护的多名学生之间切换，默认选择主监护学生；请求无监护关系学生返回 403，学生上下文不返回手机号、性别等隐私字段。
- 学生档案列表不再直接序列化实体；普通查看角色获得脱敏手机号，拥有 `education:student:privacy:view` 的角色获得完整手机号，两种权限响应已通过真实账号对比验证。
- 学生档案 XLSX 导出同时校验 `education:student:export` 和隐私字段权限；两种真实角色导出的脱敏/完整号码没有交叉泄露，导出数量及隐私级别已写入审计日志。
- 自动排课可生成 1～5 个不改动当前草稿的候选方案，支持全量和指定教学任务局部重排；方案应用使用学期行锁和基线哈希阻止过期方案覆盖他人修改。

- 教育数据权限已扩展通用资源标识，并覆盖学生、班级、教师、监护关系、任教关系和教学班成员的列表、导出与变更边界；真实账号验证全校范围返回 60 名学生，指定班级范围仅返回目标班级 10 名学生，两份 XLSX 导出数量一致。
- 教育数据权限新增越权回归测试，覆盖跨班学生访问、年级授权访问、班级跨年级移动、校区范围展开和课表全校维度拒绝；教育模块当前 9 项测试全部通过。
