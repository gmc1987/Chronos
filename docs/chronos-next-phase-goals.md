# Chronos 下一阶段目标与验收清单

更新日期：2026-09-30。适用范围：当前 `Chronos`、`Chronos-UI` 工作区及 `ChronosEducation` 数据库。本清单用于后续逐项实施和关闭问题，不将“已有页面或代码”“旧文档标记完成”直接等同于生产验收。

## 基线与判定规则

- 第一阶段智慧校园二十项能力已有较广的实现基础；2026-09-30 初次重跑旧就绪脚本为 18/20，阶段 A 修复授权并校正 IAM 关系表检查后为 **20/20 PASS**。这只证明数据库就绪，不等于业务端到端验收。
- `EDU_ACADEMIC_APPROVER` 的两项 Agent 权限原本未授予。新增 `V20270108` 幂等迁移后，IAM 启动归一化将它们存入 `t_role_menu_permission`；第 18、19 项就绪检查已按实际鉴权数据源修正。新版 AI 排课 Run 仍要求独立的全校排课权限。
- AI 走班排课的 Run、澄清、确认、候选生成、Skill/Tool 基座和页面已经入库；旧方案文档的“待实现”是历史状态。当前需求解析主要依靠确定性规则，完整的大模型结构化理解及端到端生产验收仍未完成。
- 一项工作只有在当前代码、数据库迁移、普通角色权限、真实业务链路、失败恢复和必要的前后端验证均有证据后，才能标记为“生产级完成”。只通过构建或只用超级管理员演示，标记为“代码完成／待验收”。

## 阶段 C：上线保障与生产增强

| ID | 目标 | 交付与验收标准 |

| C1 | 配置、迁移与恢复 | 医院应用移除开发默认密钥、密码、Druid 账号和 `ddl-auto=update`／Flowable 自动改表的生产风险；验证新库初始化、旧库升级、备份恢复与回滚。教育应用也要在目标环境复验迁移。 |
| C2 | 安全与可观测 | 普通用户和跨校区权限矩阵、文件扫描、审计保留/归档、关键指标、告警和事故重放形成运维手册；组织与授权变更增加影响分析。 |

| C4 | 容量与复杂规则 | 使用目标学校实际规模做排课和考试并发压测、容量上限及故障恢复；补充高级软约束、跨校区通勤和复杂多人流程的浏览器验收。 |
| C5 | 外部渠道与移动端 | 短信、邮件、企业微信、统一身份与移动端按实际供应商和交付范围接入；缺少供应商、凭证或目标客户端时，保持“待外部条件”状态，不声称生产完成。 |

## 执行顺序和关闭方式

先完成 **A1→A2→A3**，建立可相信的当前基线；随后并行推进 B1—B5 的互不冲突部分，B6 需要先冻结医院首批业务范围；最后统一完成 C 类上线保障。每个 ID 关闭时记录：变更文件、迁移版本、真实角色、业务数据、通过/失败结果、遗留风险和复测入口。阶段完成的判定以这些证据为准，而非仅以勾选清单为准。
