# AI 排课与普通排课能力对齐进展

本轮先消除了生成范围不一致：AI Run 请求和确认计划现在保存每周上课天数、每日节数、开始周、结束周；澄清重解析保留这些参数，生成前按学期教学周数和本轮时段重新校验。旧 Run 没有这些字段时，沿用原来的学期作息默认值。AI 页面提供与普通排课相同的时间范围输入，并可从候选列表跳转普通排课完成审核、应用和版本发布。

两种模式已共用 `ScheduleGenerationJobService` 和 `AutoSchedulingService`。因此正式教学任务、教师时间约束、教师负荷、学生与教室占用、教室不可用时段、锁课和学校排课策略均从同一服务读取；AI 的本轮规则作为附加 `ScheduleRunConstraints` 进入同一求解器。候选的审核、应用、发布仍须通过现有人工流程。

尚不能宣称“自然语言覆盖普通排课所有能力”：模型分类与服务端编译仅支持教师时段、课程连堂偏好、教学周、临时锁课、教师软偏好和组合禁排。校历节假日、补课、请假代课、考试覆盖属于日期课表业务，目前由 `ScheduleOccurrenceService` 处理，不属于 AI 自然语言可编译规则。人工课表增删改、导入、规则配置、候选审核和发布也未作为 Agent Tool 开放。下一步应建立带版本的规则目录及逐条验收清单，按规则类型接入权威数据、求解和结果核验；日期级请求需要独立于周课表的受控调整流程。

浏览器验收（仅在持久化验收副本 `chronos_schedule_verify_20261002`）：以 `showcase.admin` 在 2026—2027 第一学期创建全量 Run `e645d775-48f8-41e7-9e6a-9e3742d7e429`，确认解析计划并生成 3 个候选。3 个候选均已排 61 节、未排 0 节；候选课表各含 54 个课表项（连堂按节数展开后为 61 节）。AI 页可预览差异，跳转普通排课页后 3 个候选出现在相同的候选列表；第 3 号方案已提交审核，状态为“待审核”，尚未由异人审核、应用或发布。此前创建失败的原因有两个：开发服务未带 `VITE_CHRONOS_INDUSTRY=EDUCATION` 导致教育路由未加载；Agent 把校区为空、可由求解器选择教室的公共课误判为缺少默认作息，现已修正。创建失败原因会持续显示在表单上。

## 2026-10-03 日期规则与确认审核增量

Agent 现在能识别三种受控自然语言意图：按学校校历处理节假日与调休、按考试计划处理考试占课、按已批准教师请假处理代课。Run 计划保存这些意图，日期影响接口读取当前工作课表、校历、待补课、已批准请假的待代课课次及考试计划受影响课次；具体日期变更不会由大模型直接写入。任意新增休假日期或未明确政策的补课日期仍须先维护校历，不能从自然语言猜测。

AI 页面可从单条待补课/待代课直接打开预填的日期调整表单，也可从考试计划跳到对应占课审批页面。目标补课日期、节次、代课教师等由教务确定，保存日期调整时复用原有教师、教室、学生及教学日硬冲突校验。当前影响按**工作课表**计算，应用候选周课表后必须重新核对；候选周课表本身不结清日期待办。考试占课继续走考试中心的申请和异人审批。

AI 候选可在 AI 页面预览相对当前课表的增删移动差异，用户确认后提交既有候选审核；审核人与提交人分离，审核、应用和发布仍走普通排课的治理链路。浏览器在持久化验收副本创建 Run `e84287cd-30e7-47df-9f17-f529838ee1e5`，三类日期意图均进入计划，生成三个已排 61 节、未排 0 节的候选。第 3 号候选由 `showcase.admin` 提交，状态为“待审核”，未自审、未应用、未发布。页面展示特殊校历 13 天、当前待补课 65 节、待代课 0 节、考试计划 3 个（其中一项受影响 2 节）；已验证从 Agent 单条补课打开预填表单、从考试影响行选中对应考试计划。演示库没有已批准教师请假导致的待代课课次，故代课路径尚未做真实记录验收。

本增量的边界：Agent 尚不自动选定补课目标时段或代课教师，也不为每个候选重新计算日期影响；日期调整尚没有 Agent 独立的草稿与审核队列。三类日期规则已经纳入识别、权威数据影响核对和现有受控业务流程，但不能宣称已完成自动化日期排课。未来若需自动提议，必须在候选快照上计算并校验具体日期/资源，提交审核后再生效。
