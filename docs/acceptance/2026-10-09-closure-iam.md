# 教育排课普通角色与学校范围增量验收

## 环境

浏览器与 HTTP 验收使用独立数据库 `chronos_handoff_verify_20261009`、后端 `18089` 和教育前端 `5189`。只修改副本中的验收角色 `ACCEPT_SCHEDULING_MANAGER`：先从 `ALL` 改为星河高职学校范围，再补齐排课维护页依赖的机构、课程、场地只读权限。源库角色与课表未修改。

## 发现与修复

- 演示学校直接把学校组织 ID 写入教学任务 `campusId`，但原作用域解析只把学校下属 `CAMPUS` 加入校区集合。副本没有独立校区组织，导致本校 504 个教学任务对受限角色显示为 0。修复后学校 ID 本身也作为可访问的校区 ID，同时保留子校区。见 [修复前](2026-10-09-school-scope-before.png)和[修复后教师课表](2026-10-09-school-scope-after.png)。
- 教师筛选原先只读取个人 `teacherIds`；学校范围管理人员因此无法选择本校教师。修复为并入本校教学任务涉及的教师。浏览器可选本校 68 名教师，选择 `SCALE-HV-T007` 后显示其本人周课表。
- 受限角色默认请求“全校课表”和调课事故等全局接口，会显示 403 提示。排课维度选项现在返回 `fullAccess`；受限角色默认选择教师维度，只展示授权范围内可用页签和按钮，不发起全局版本、候选、质量、规则、事故请求。浏览器复验不再出现越权提示。具有 `ALL` 数据范围的角色仍显示完整页签；独立审核员仍仅显示候选审核页签。见 [审核员回归](2026-10-09-reviewer-regression.png)。

## 权限边界

| 同一普通账号令牌的操作 | 实际结果 |
| --- | --- |
| 列出本校 2026–2027 第一学期教学任务 | 200，共 504 条 |
| 按本校教学班 ID 读取周课表 | 200 |
| 按另一所学校的教学班 ID 读取周课表 | 403 |
| 使用 `ALL` 维度读取全校课表 | 403 |
| 发布全校课表 | 403；副本版本未因此新增 |
| 角色学校范围从高职改为专科学院 | 同一令牌可见数立即从 504 变为 12，恢复后回到 504 |
| 同时撤销角色直接授权和菜单授权中的课程查看权限 | 同一令牌从 200 立即变成 403；恢复后 200 |

撤权时只删除一张授权表中的记录仍返回 200，因为另一张表存在有效授权；这不是令牌缓存失权故障。实际角色维护必须核对两条授权来源。

后端 `EducationDataScopeServiceTest` 通过，教育后端重新打包成功，前端生产构建通过。此项仅关闭学校范围排课的这组问题；教师、学生、家长、班主任、督导、流程参与者全矩阵及跨组织其他业务仍由台账 #02 跟踪。
