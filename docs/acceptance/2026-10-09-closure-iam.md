# 教育排课普通角色与学校范围增量验收

## 环境

浏览器与 HTTP 验收使用独立数据库 `chronos_handoff_verify_20261009`、后端 `18089` 和教育前端 `5189`。只修改副本中的验收角色 `ACCEPT_SCHEDULING_MANAGER`：先从 `ALL` 改为星河高职学校范围，再补齐排课维护页依赖的机构、课程、场地只读权限。源库角色与课表未修改。

## 发现与修复

- 演示学校直接把学校组织 ID 写入教学任务 `campusId`，但原作用域解析只把学校下属 `CAMPUS` 加入校区集合。副本没有独立校区组织，导致本校 504 个教学任务对受限角色显示为 0。修复后学校 ID 本身也作为可访问的校区 ID，同时保留子校区。见 [修复前](2026-10-09-school-scope-before.png)和[修复后教师课表](2026-10-09-school-scope-after.png)。
- 教师筛选原先只读取个人 `teacherIds`；学校范围管理人员因此无法选择本校教师。修复为并入本校教学任务涉及的教师。浏览器可选本校 68 名教师，选择 `SCALE-HV-T007` 后显示其本人周课表。
- 受限角色默认请求“全校课表”和调课事故等全局接口，会显示 403 提示。排课维度选项现在返回 `fullAccess`；受限角色默认选择教师维度，只展示授权范围内可用页签和按钮，不发起全局版本、候选、质量、规则、事故请求。浏览器复验不再出现越权提示。具有 `ALL` 数据范围的角色仍显示完整页签；独立审核员仍仅显示候选审核页签。见 [审核员回归](2026-10-09-reviewer-regression.png)。

## 权限边界

| 同一普通账号令牌的操作 | 实际结果 |
| --- | --- |
| 列出本校 2026–2027 第一学期教学任务 | 200，共 504 条 |
| 按本校教学班 ID 读取周课表 | 200 |
| 按另一所学校的教学班 ID 读取周课表 | 403 |
| 使用 `ALL` 维度读取全校课表 | 403 |
| 发布全校课表 | 403；副本版本未因此新增 |
| 角色学校范围从高职改为专科学院 | 同一令牌可见数立即从 504 变为 12，恢复后回到 504 |
| 同时撤销角色直接授权和菜单授权中的课程查看权限 | 同一令牌从 200 立即变成 403；恢复后 200 |

撤权时只删除一张授权表中的记录仍返回 200，因为另一张表存在有效授权；这不是令牌缓存失权故障。实际角色维护必须核对两条授权来源。

后端 `EducationDataScopeServiceTest` 通过，教育后端重新打包成功，前端生产构建通过。此项仅关闭学校范围排课的这组问题；教师、学生、家长、班主任、督导、流程参与者全矩阵及跨组织其他业务仍由台账 #02 跟踪。

## 2026-10-11 家长普通账号与即时失权增量

在同一隔离库、同一浏览器会话使用普通家长 `demo-parent-hv-001` 验收。该账号绑定家长档案 `347a4cf8-2a9a-43ac-9745-cf818b2cbbbe`，监护关系仅指向学生 `9f29a286-59d2-8d12-04bf-ddb1fd324d04`（演示学生001-01）。浏览器家长门户只出现这一名孩子及其班级通知、已发布成绩。直接输入后台机构管理地址时，服务端原已返回 403，但页面会显示空表；现给机构路由增加与列表接口一致的只读权限门槛，普通家长直达后回到门户。

在保持该浏览器登录令牌不变的情况下，只在隔离库将家长绑定从 `ACTIVE` 暂改为 `INACTIVE` 并点击页面“刷新”。接口立即返回 403。发现原页面仍保留之前显示的孩子、通知和成绩；已修复为每次加载先清空旧数据，失败时保留可见的错误提示。浏览器复验失权后显示“无权访问该资源”，不再显示孩子、通知、成绩。随后恢复绑定为 `ACTIVE`，同一令牌再刷新，原有一名孩子和对应数据重新出现。用于登录的临时演示密码哈希也已恢复为原值，临时备份文件已删除。

前端 `npm run build` 通过。此处只验证了家长绑定即时失权及机构入口；跨校区、跨组织、班主任、教务、督导、流程参与者和组织授权影响分析仍未完成，#02 不关闭。本轮没有生成新截图。

## 2026-10-11 停用机构与授权影响增量

原数据范围解析会直接采纳角色保存的机构和部门 ID，即使机构已停用。现解析时重新核验机构及其上级机构、部门及其上级部门的状态；普通账号持有的原登录令牌不需要重新签发。`DataScopeServiceOrganizationStatusTest` 覆盖上级学校和上级部门停用/恢复边界。

浏览器以普通排课管理 `accept.scheduling.manager` 的同一登录会话验证：学校 `9f1fee10-1c2e-b6e9-2e68-50e6f32cc65e` 启用时教学任务总数 504；仅在隔离库暂时停用该学校并刷新后为 0；恢复学校并刷新后重新为 504。数据库最终学校状态恢复为 `1`。管理员进入机构管理，点击该学校“删除”只查看确认框，确认框列出下级机构 0、部门 1、任职 69、账号 8038、角色数据范围 3；随后取消，机构未被浏览器操作停用。影响提示新增了下级机构和角色数据范围计数。临时测试密码哈希均已恢复。

后端目标测试和聚合打包、前端生产构建通过。本场景只验证停用机构对显式机构范围的即时影响；其他组织变更、跨机构任职与更多普通角色边界仍待验收，#02 保持进行中。本轮没有生成新截图。

## 2026-10-11 服务重启后普通角色回归

验收服务退出后，重新核对 `18089` 后端只连接 `chronos_handoff_verify_20261009`，以原配置启动 `5189` 教育前端。普通教师 `scale-hv-t007` 重新登录，门户正常显示本人课表和 3 个班主任班级，所带班级分别有 46、50、48 名在籍学生。普通教务审批人 `scale-hv-t006` 登录后台学生档案，列表为高职学校的 7,968 人；隔离库按学校对账为高职 7,968、大专 190、本科 190，未在该角色列表混入其他两校数据。同一普通教务审批账号对本校行政班 `cfcb4ea7-c04f-aeef-c22f-09599985d9c6` 的学生查询返回 200、48 人；对大专行政班 `4ef42e8e-3125-9251-eb69-71b584b38e6f` 返回 403。测试期间两名账号仅临时使用已知本地验收密码，完成后恢复原密码哈希并删除临时备份表；临时令牌文件也已删除。

代码复核发现失效的角色数据范围若引用了已不存在的机构或部门，原状态判断会误判为有效；已改为缺失即失权，并在 `DataScopeServiceOrganizationStatusTest` 增加缺失机构、缺失部门用例。目标测试、教育后端聚合打包通过；重启新包后，同一普通教务审批人会话刷新学生档案仍显示本校 7,968 人。

## 2026-10-12 督导角色权限边界增量

权限矩阵核查发现督导任务查看、接受、签到和评价等权限只授予系统管理员，普通教师角色却拥有任务分配及复查权限；`assignment:update` 接口所要求的权限码甚至未定义。迁移 `V20270140` 新增“教学督导管理员”和“教学督导员”两个分离角色及缺失权限码，撤销普通教师的任务分配、复查权限。隔离库 Flyway 成功应用到 `20270140`，迁移版本扫描通过，无重复版本。仅在隔离库将管理员角色赋予 `scale-hv-t006` 并限定高职学校组织，将督导员角色赋予 `scale-hv-t007`，保留作后续督导业务演示账号。

浏览器以普通教务人员 `scale-hv-t006` 打开督导管理页，可读取空计划列表；以普通督导员 `scale-hv-t007` 打开“我的督导任务”，可读取空任务列表。接口复核：督导员任务列表 200、无督导角色的普通教师 `scale-hv-t008` 为 403；针对校方任务分配接口，以有效字段但不存在的计划 ID 发起无副作用边界请求，管理员角色进入业务层，督导员及普通教师均被权限层拒绝为 403。最初不存在的计划返回通用 500，已修复为 400 和明确的“督导计划不存在”；目标测试、聚合打包和新包运行态复验通过。该请求没有创建任务，不能把它当成成功分配。角色临时登录密码已恢复，临时令牌文件已删除。

本段只核查督导角色授权边界。尚无真实督导计划、任务和跨校区任务数据，因此不能作为 #14 督导闭环或 #02 完整矩阵通过的证据。

## 2026-10-12 成绩审核与发布角色增量

普通成绩审核员 `scale-hv-t005` 在浏览器成绩中心可见高职学校现有已发布成绩册。原库 `EDU_GRADE_PUBLISHER` 角色没有用户，隔离库将其单独赋予 `scale-hv-t009` 并限定高职学校组织；审核人与发布人仍是不同账号。首次登录发布人时成绩册显示空列表：该角色只有发布按钮权限，缺少查看权限，后端校内列表也仅把“审核”视为学校级查看角色。

`V20270141` 为发布角色补齐成绩册及考核方案只读权限；成绩服务将有发布权且具备学校数据范围的账号纳入校内可见列表，并在发布入口先检查目标成绩册的数据范围，避免已发布记录的幂等返回绕过范围校验。目标测试覆盖跨校已发布成绩册不得访问，聚合打包通过。隔离库 Flyway 应用到 `20270141` 后，发布人重新登录，浏览器成绩中心显示本校现有 1 本已发布成绩册；同账号接口列表为 200、1 本。未对成绩重新发布，成绩业务链仍由 #13 单独验收。临时密码与令牌文件已恢复/删除。

## #02 验收边界

2026-10-12 增加同校子校区浏览器复验。仅在隔离库临时建立高职学校下东、西两个 `CAMPUS`，将两条现有教学任务分别归属两校区，并把普通排课管理 `accept.scheduling.manager` 的组织范围从父学校切为东校区。浏览器“教学任务”只显示东校区英语任务（`Total 1`），不显示西校区数学任务；同一令牌切到西校区后只显示西校区任务（`Total 1`），东校区任务不可见；切回父学校范围后显示原有 `Total 504`，说明父学校可展开两个子校区。随后恢复两条任务的原校区、角色原学校范围和账号原密码，删除临时两个校区；对账两条任务和角色范围均恢复。此前普通角色跨学校详情 403、菜单/角色双来源撤权即时生效等边界仍见上文。这是临时子校区样本的浏览器范围验证，不代表真实校区业务数据已建成。

按 #02 定义汇总普通角色边界：排课管理与异人审核、教师与学生本人课表、家长单子女与失权、班主任本班与他班、教务审批人本校与跨校、督导管理员与督导员及无角色教师、成绩审核人与发布人，以及流程发起人、候选人和实际处理人，均有上述浏览器或接口证据；组织停用、授权范围调整和双授权来源撤销都在同一令牌上复验。#02 的权限边界在隔离库通过。实际督导、成绩、家校和工作流完整业务状态仍分别由后续专项验收，不将权限验证代替业务闭环；生产部署与真实子校区数据仍需上线验收。

当前隔离库的三所学校直接把学校 ID 用作班级、教学任务的 `campusId`。因此本轮普通角色浏览器验证了实际数据中的跨校区 ID 隔离（本校 200、异校 403）；同一学校下的独立子校区没有对应业务数据，父学校/子校区展开及校区间课表资源隔离由 `EducationDataScopeServiceTest` 覆盖，不能称为真实子校区浏览器演练。督导管理员/督导员、成绩审核员/发布人、排课负责人/审核员、教师/学生/家长/班主任及流程发起人/候选人/实际处理人的职责边界已有上述浏览器或接口证据；督导、成绩的完整业务状态流分别留给 #14、#13。
