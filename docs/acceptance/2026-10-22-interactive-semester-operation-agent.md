# 交互式学期运营智能体验收

## 验收范围

- 管理端和门户端统一提供右上角“智能体视图”入口，视图宽度约占桌面屏幕的六分之一，并支持随时收起和重新展开。
- 执行计划支持新增、编辑、删除、启停、手动执行和 Cron 周期执行；计划可配置目标、规则、规划周期、知识库、授权业务工具及有序步骤。
- 执行过程支持步骤进度、下一步计划、事件时间线、暂停、继续、取消、人工确认和运行中附加条件。
- 高风险和关键写入工具必须在正式业务写入前停在人工确认点；计划、工具授权、条件版本、审批人和步骤结果均建立快照并留痕。

## 生产控制边界

- 低风险检查工具可以自动执行；高风险和关键写入工具由服务端强制要求人工确认，前端不能绕过。
- 暂停请求在安全检查点生效，已完成步骤不会因附加条件被静默覆盖；条件只影响尚未开始的步骤。
- 当前可执行自然语言条件覆盖入学年份、批次上限、学期编码和禁止正式写入。超出该结构的条件仍会完整留痕，但需要扩展条件规则或对应业务工具适配器后才能自动执行。
- 知识库检索已作为授权工具接入，计划可以绑定知识库；检索结果用于政策依据和执行证据，不直接获得业务写入权限。
- 当前工具目录共 20 项，覆盖学期检查、知识检索、新生导入与建档、学生和教师账号、教师任教关系、教学任务、全量排课、异人审核、应用发布、期末检查与毕业待办。写入复用现有领域服务，不允许模型直接拼接 SQL 修改业务表。

## 执行计划删除与历史审计修复（2026-10-22）

- 修复已有运行历史的执行计划无法删除的问题。根因是 `edu_operation_agent_run.plan_id` 使用默认限制型外键，删除计划时仍被历史运行引用。
- 外键调整为 `ON DELETE SET NULL`，同时允许历史运行的 `plan_id` 为空。删除计划后，运行快照、步骤证据、附加条件、审批记录和事件仍然保留。
- 运行列表继续通过已保存的计划快照和“已删除计划”占位名称展示历史，不会因为计划删除而丢失审计链。

### AI 计划生成 V2 重构（2026-10-23）

- 生成入口已经移除“开学七阶段全流程/局部计划”选择。用户只描述目标并按需提供学期、入学年份、知识库和名册文件，七阶段仅作为内部工具依赖图。
- 调用 DeepSeek 前先从真实数据库生成准备度快照；模型只选择实现目标仍需执行的工具，服务端继续执行工具白名单、重复步骤去除和阶段依赖排序。
- 工具目录声明必需参数。教师分工缺少 `assignments`、名册导入缺少受管文件 ID 或排课缺少学期时，草案返回结构化待补充项，不再把参数缺口包装成模型失败。
- 候选模式默认开启。新生导入、拟分班、资格复查、报到建档、账号开通、教师入职、教师分工和开课生成均传入 `dryRun=true`；排课只生成候选，不进入提交、应用和发布。
- 执行器在每一步前再次检查有效参数。缺失时步骤进入 `WAITING_INPUT`，运行在安全检查点暂停；用户补充资料后保留审计记录并从该步骤继续。
- 浏览器使用真实 DeepSeek 和数据库验证：“检查 2026-2027-1 学期排课条件”只生成学期检查和教学准备度检查两个只读步骤，同时展示学期、177 个行政班、8350 名学生、78 名教师、531 个开课任务、15 个排课候选和 4 个已发布课表版本的准备度快照。
